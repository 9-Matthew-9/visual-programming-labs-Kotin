# Лабораторная работа №4 — n8n

## Цель

Освоить n8n как среду автоматизации: собирать workflows из узлов, обрабатывать данные, отправлять HTTP-запросы, запускать процессы по расписанию и работать с Redis.

## Установка

n8n запускается в Docker-контейнере `n8nio/n8n` на порту `5678`. Настройки и workflows хранятся в `lab4/n8n_data`, а файлы лабораторной доступны контейнеру в `/data` через папку `lab4/data`.

Локальный адрес: `http://localhost:5678`.

Версию n8n нужно записать после запуска командой `docker exec n8n n8n --version`.

## Выполненные workflows

- `flow-01-manual-set.json` — Manual Trigger, Set и Code; передача фамилии и topic.
- `flow-02-code.json` — JavaScript: переменные, условия, цикл, массив и объект.
- `flow-03-if.json` — ветвление через IF.
- `flow-04-set.json` — изменение полей сообщения и времени.
- `flow-05-http.json` — GET-запрос к публичному API.
- `flow-06-schedule.json` — выполнение по расписанию.
- `flow-09-redis.json` — запись и чтение ключа Redis.
- `flow-10-redis.json` — удаление ключа и проверка его отсутствия.
- `flow-11-pinggy-webhook.json` — публичная status-точка, которая возвращает JSON с информацией о лабораторной работе.

Каждый workflow необходимо импортировать в n8n, выполнить и экспортировать после проверки. Redis-узлам нужно назначить созданные в интерфейсе credentials.

## Индивидуальная ачивка: 4.N — туннель Pinggy

В качестве индивидуальной вариации выбрана ачивка о временном публичном доступе к локальному n8n через другой туннельный сервис — Pinggy. Pinggy не входит в перечисленные в задании Cloudflare Tunnel, Ngrok, Localtunnel и Serveo.

Для демонстрации добавлен workflow `flow-11-pinggy-webhook.json`. Он отвечает JSON-объектом со статусом, названием проекта, студентом, группой и временем запроса. После запуска n8n workflow активируется, затем туннель Pinggy временно публикует локальный порт `5678`. Проверка выполняется открытием публичного HTTPS-адреса с путём `/webhook/lab4-kotin-status`.

Туннель временный: терминал с SSH-подключением должен оставаться открытым. После демонстрации туннель закрывается через `Ctrl+C`. Не следует публиковать секреты, токены или данные учётной записи.

## AI

AI использовался для планирования структуры workflow, подготовки примеров Code, подбора публичного HTTP API и создания JSON-заготовки status webhook. После импорта результаты нужно проверять в интерфейсе n8n.

Примеры запросов к AI:

- «Подготовь workflow n8n Manual Trigger → Set → Code с фамилией Kotin и полем topic».
- «Покажи пример Code node для n8n с let/const, if/else, циклом for, массивом и объектом».
- «Составь workflow n8n для записи и чтения значения в Redis, а затем отдельный workflow для удаления ключа и проверки отсутствия».
- «Создай простой GET webhook в n8n, который возвращает JSON со статусом, фамилией, группой и текущим временем».
