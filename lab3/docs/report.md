# Лабораторная работа №3 — Bubble

## Что я сделал

Я создал публичный каталог гаджетов в Bubble. Сначала AI сгенерировал основу приложения, потом я вручную доработал интерфейс: добавил цветовую переменную и готовый компонент.

В базе данных используется тип «Устройство». Я добавил три записи и создал отдельную страницу `devices_admin` для управления каталогом.

На странице реализованы четыре CRUD-операции:
- **Create** — добавление устройства;
- **Read** — просмотр и поиск;
- **Update** — редактирование;
- **Delete** — удаление с подтверждением.

Работу основных операций я проверил в Preview.

## Дополнительная ачивка — API Connector

Я подключил внешний тестовый API JSONing через Bubble API Connector. Настроил запросы GET, POST, PUT и DELETE и добавил отдельный блок внешнего каталога на страницу приложения.

<summary>5. Подключение внешнего API</summary>

На существующей странице devices_admin добавь отдельный раздел внизу страницы с заголовком «Внешний каталог гаджетов — API Connector».

Важно: не изменяй и не удаляй существующий каталог, его базу данных и уже работающие workflows CRUD. Новый раздел должен работать отдельно с внешним JSONing API через уже настроенные вызовы в API Connector.

1. READ: используй существующий вызов Get Gadgets из API Connector (Use as Data). Покажи полученный список внешних гаджетов в виде повторяющихся карточек. Для каждого гаджета отображай id, name, category и price. Не используй для этого локальный тип данных Bubble «Устройство».

2. CREATE: добавь форму с полями названия, категории и цены, а также кнопку «Создать во внешнем API». Workflow должен вызывать существующий Create Gadget (POST), передавать значения из формы и после успешного ответа обновлять отображаемый список.

3. UPDATE: добавь редактирование выбранного гаджета. При нажатии «Редактировать» загружай его id, name, category и price в поля формы. Кнопка «Сохранить изменения» должна вызывать существующий Update Gadget (PUT), передавать id выбранной записи и новые значения полей.

4. DELETE: добавь кнопку «Удалить» у каждой карточки внешнего каталога, запрос подтверждения и вызов существующего Delete Gadget (DELETE) с id выбранной записи. После удаления обновляй список.

Все четыре операции должны использовать именно существующие вызовы API Connector, а не внутренние действия Bubble Create a new thing, Make changes to a thing или Delete a thing.

Если невозможно настроить обновление списка после действия, создай отдельную кнопку «Обновить внешний список», которая повторно загружает данные через Get Gadgets.

После выполнения перечисли, какие элементы и workflows созданы, и укажи, какие части требуют ручной настройки или проверки.
